# Record of AI assistance

Kept so the disclosure in the report is accurate rather than approximate, and so
I know exactly which parts of the repository I need to be able to defend without
notes. The summary statement is in the report's *AI assistance disclosure*
section; this file is the detail behind it.

Every number in the report and in `results/` comes from running the code on the
real dataset. No result was written, estimated or adjusted by hand. The only
invented values anywhere in the project are the small fixtures in the unit tests,
which are labelled as such in each test module's docstring.

## Post-submission engineering pass

A review of the repository against the assignment rubric, followed by the
changes below. This pass did not retrain any model in the study and did not
change any number in the submitted report. `verify_submission.py` was run before
and after and passes on all 45 saved models; the regenerated tables in
`results/` are byte-identical to the committed ones.

Structure and style:

- Split `experiments.py` into `protocol.py` (split boundaries, seeds, model
  registry), `features.py` (windowing, splits, scaling) and `models.py` (model
  definitions), leaving `experiments.py` as training orchestration.
- Rewrote `render_report.py`, `download_data.py`, `download_remaining.py`,
  `predict_saved.py` and `run_final.py` in a consistent style. The rendered PDF
  was compared before and after: identical page count and identical extracted
  text.
- Removed duplicated logic: one `file_md5`, one seed list, one model list, one
  set of split boundaries. `verify_submission.py` deliberately still derives the
  split dates from date strings, so it can catch a wrong constant rather than
  agree with it.
- Added type hints and docstrings to the public functions in the pipeline
  modules, and a `pyproject.toml` holding only optional `ruff` configuration.

Reproducibility:

- `reproduce.py` and a `Makefile` as a single entry point, with the four tuning
  rounds scripted for the first time.
- A GitHub Actions workflow that installs the recorded environment, runs the
  tests, rebuilds the results and fails if any regenerated table differs from
  the committed one.

Tests, from 20 to 28:

- The leakage guarantee is now checked at five different lookbacks rather than
  one.
- The scaler is asserted to equal the training-slice statistics directly, not
  only to be invariant when later data changes.
- Round-trip tests for the normalization and for the correction target.
- `test_report_provenance.py` pins each numeric claim in the report to the
  artifact that produces it.
- The new leakage and round-trip tests were checked by deliberately breaking
  `features.py` four ways (fitting the scaler on all data, making eligibility
  depend on lookback, and lowering the precision of the history and of the
  correction). Each mutation is caught.

Analysis added from results that already existed, with no retraining:

- `compare_seeds.py` and `results/seed_separation.csv`, which ask whether each
  area's model ranking is larger than its seed-to-seed spread.
- `adf_specifications.py` and `results/adf_specifications.json`, so both ADF lag
  specifications discussed in the report are produced by running code rather
  than quoted from a run that was not saved.

Appendix experiments, run after submission and reported in `results/appendix/`.
These are additional evidence about the tuning process. They do not change any
configuration used in the study and do not affect any reported metric.
